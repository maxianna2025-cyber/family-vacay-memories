
## 1. Карта операции — полная переделка

Текущая карта — синтетический «чертёж»: контур страны нарисован одним угловатым полигоном, надписи стран висят в пустоте, точки городов слиплись (Гонконг 540/360 и Макао 532/362 — 2 пикселя друг от друга). Это и страшно, и нечитабельно.

Что сделаю:

- **Заменю самодельный SVG-полигон** на корректный векторный контур восточной Азии (использую упрощённые, но географически узнаваемые контуры суши: Россия (юг Сибири), Монголия, Китай, Корея, Япония, Вьетнам, Филиппины, Тайвань). Контуры возьму из открытого датасета (Natural Earth simplified) и встрою как inline-SVG — без сетевой загрузки.
- **Цветовая иерархия:** море — тёмный фон карты; суша — мягкий тёплый бежевый/хаки на 12% непрозрачности (хорошо контрастирует с оранжевым маршрутом); границы стран — тонкая линия muted-foreground; страны подписаны «вглубь» суши, а не поверх моря.
- **Точки городов разнесены по реальным координатам** (lon/lat → проекция на viewBox 800×520):
  - Красноярск ~ 92.9 / 56.0
  - Пекин ~ 116.4 / 39.9
  - Гонконг ~ 114.2 / 22.3
  - Дананг ~ 108.2 / 16.0
  - Макао ~ 113.5 / 22.2 (рядом с Гонконгом — но теперь подпись Макао пойдёт ВЛЕВО, а Гонконга — ВПРАВО, плюс лидер-линия от точки к подписи)
- **Маршрут:** оранжевая дашед-линия с лёгкой кривизной (как на референсе), плавная прозрачность пройденных участков (1.0) vs будущих (0.4).
- **Маркеры:** круг 8px + кольцо. Пройденные — заливка orange + ✓. Активный — pulse-кольцо. Будущие — пустой круг с обводкой.
- **Подписи городов:** в плашке (rect 2px padding с фоном card/90) — чтобы текст не сливался с сушей и не наезжал на соседнюю подпись. Дата под названием в моноширинном.
- **Декор:** компас в правом верхнем, штамп «ИЮЛЬ 2026» в левом нижнем — оставляю, но более тонкие, opacity 0.4, чтоб не отвлекали.
- **Шапка карты:** статус и счётчик 0/6 — оставляю.

Результат: карта читается с одного взгляда, видно «откуда → куда», все 6 точек различимы, Гонконг и Макао не слипаются.

## 2. Несколько заданий на каждый город

Сейчас на сектор есть одно поле `mission` в таблице `sectors`, плюс `additional_tasks` с `sector_slug`. Унифицирую вокруг `additional_tasks` — там удобнее добавлять/корректировать/удалять.

**Админка `/admin` — секция «Задания по городам»:**

- Группировка существующих заданий по городу (Все · Пекин · Гонконг · Дананг · Макао).
- В каждой группе — список карточек с заданиями. На карточке:
  - inline-редактирование текста (textarea + кнопка «Сохранить»)
  - кнопка «×» удалить
  - выпадайка «переместить в город»
- Под каждой группой — поле «Добавить ещё одно задание для <город>» + кнопка. Можно лить пачкой.
- Старая отдельная секция «Дополнительные задания» удаляется (поглощается этой).

**Агент `/agent?sector=<slug>`:**

- В карточке города брифинг + СПИСОК заданий (всех с `sector_slug = <slug>` плюс «общие» с `null`), по чек-листу. Нумерация «Задание 1 / 2 / 3».
- Поле `sectors.mission` остаётся как «главная цель» — отображается отдельно над списком, либо мы выводим её первой строкой в списке. Предложу: оставить как «Главная цель сектора» (одна строка), а доп. задания — нумерованным списком ниже.

**Главная `MissionTasksCard`:**

- Показывает 4 последних задания с бейджем города. Без изменений по сути, просто теперь их станет больше и они будут с привязкой.

**Страница `/tasks`:**

- Группировка по городу (4 секции + «Общие»). В каждой — карточки с датой и автором (как сейчас).

## Технические изменения

**Backend (server functions):**

- `adminUpdateTask(password, id, task_text, sector_slug)` — новая функция (UPDATE по id).
- `adminAddTask` — без изменений (уже принимает `sector_slug`).
- `adminDeleteTask` — без изменений.

**Миграция БД:**

- Добавить RLS-политику `UPDATE` для `additional_tasks`? Нет, апдейт пойдёт через service role в server function — RLS не нужен.
- Никаких schema-изменений не требуется.

**Файлы:**

- `src/components/RouteMap.tsx` — полная переделка SVG (контуры суши, проекция координат, разнесённые подписи, лидер-линии).
- `src/routes/admin.tsx` — секция заданий: группировка по городу, inline-редактирование, добавление.
- `src/routes/agent.tsx` — внутри карточки сектора показать список доп. заданий из `additional_tasks` (фильтр по `sector_slug`).
- `src/routes/tasks.tsx` — группировка по городу.
- `src/server/admin.functions.ts` — `adminUpdateTask`.
- `src/lib/api/cloud.ts` (и `amvera.ts` если используется) — метод `listTasksBySector(slug?)` или просто фильтрация на клиенте из `listTasks()` (проще, т.к. заданий немного).

После одобрения — выкатываю всё одним проходом и пришлю скриншоты карты на мобильном (464px) и десктопе.
