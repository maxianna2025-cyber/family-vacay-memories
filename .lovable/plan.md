
# Спецотряд: Саянская Вершина — план

Семейное веб-приложение для отпуска: фото с подписями и городами, комментарии и «дополнительные задания» для детей. Сейчас всё работает на Lovable Cloud; в будущем легко переключить на ваш Amvera-бэкенд (Express + PostgreSQL) через прокси без переписывания UI.

## Доступ
- Без авторизации — любой по ссылке заходит в приложение.
- При первом входе пользователь сам вводит своё имя (свободный текст, до 40 символов). Имя сохраняется в `localStorage` и подставляется в комментарии и задания. Можно сменить в шапке.

## Экраны

1. **Главная — Лента** (`/`)
   - Шапка: название «Спецотряд: Саянская Вершина», текущее имя пользователя с кнопкой «сменить».
   - Кнопка «Загрузить фото» → модалка: файл, город, подпись, агент.
   - Карточки фото в ленте: изображение, город, подпись, автор-агент, дата.
   - Под каждым фото — комментарии и поле «написать комментарий».

2. **Задания** (`/tasks`)
   - Форма «Отправить дополнительное задание» (textarea + кнопка).
   - Список всех заданий: автор, текст, дата.

3. **Навигация**
   - Простой верхний таб-бар: Лента / Задания.

## Стиль
Сохраняем «спецотряд»-эстетику из вашего `index.css`:
- фон `#0a0a0a`, текст `#e2e8f0`, акцент `#ff6b00` (hover `#e24e00`);
- шрифт Roboto Mono;
- карточки с тонкой оранжевой рамкой;
- адаптивно для мобильных (отпуск → телефоны).

## Данные (Lovable Cloud)

Таблицы:
- `photos` — `id`, `city`, `caption`, `agent`, `file_path`, `created_at`
- `comments` — `id`, `photo_id`, `user_name`, `comment_text`, `created_at`
- `additional_tasks` — `id`, `user_name`, `task_text`, `created_at`

Storage-бакет `photos` (публичный) — соответствует вашему `/data/uploads`.

RLS: публичное чтение и публичная вставка для всех трёх таблиц (так как доступ «по ссылке без логина»). Удаление/обновление запрещены — это безопасный минимум для семейного use-case.

Валидация на клиенте и сервере (zod): имя ≤40, подпись ≤200, город ≤80, комментарий ≤500, задание ≤500, файл ≤10 МБ, MIME `image/*`.

## Слой абстракции для будущего Amvera

Весь доступ к данным идёт через единый модуль `src/lib/api/index.ts` с интерфейсом, повторяющим эндпоинты вашего `server.js`:

```
listPhotos()              → GET /get-photos
uploadPhoto(file, meta)   → POST /upload-photo
listComments(photoId)     → GET /get-comments/:photo_id
addComment(payload)       → POST /add-comment
listTasks()               → GET /get-additional-tasks
addTask(payload)          → POST /send-additional-task
```

Реализаций две, выбор по env-флагу `VITE_API_BACKEND`:
- `cloud` (по умолчанию) — `src/lib/api/cloud.ts`, использует Lovable Cloud (Supabase JS).
- `amvera` — `src/lib/api/amvera.ts`, делает `fetch` на `VITE_API_BASE` (например `https://your-app.amvera.io`) с теми же путями, что у вас в `server.js`.

UI и компоненты импортируют только `@/lib/api` — переключение на Amvera в будущем = изменение двух env-переменных и (при необходимости) включение CORS на вашем Express.

## Что остаётся за рамками v1
- Карта Яндекса с метками городов — добавим отдельной задачей, когда дадите `YANDEX_API_KEY`.
- Авторизация и роли (если в будущем захотите ограничить доступ).
- Прямой деплой на Amvera — план готовит код к этому, но сам разворот делается, когда у вас будет готов сервер.

## Технические детали
- Стек: TanStack Start + React 19 + Tailwind v4 + Lovable Cloud (Supabase под капотом).
- Маршруты: `src/routes/index.tsx` (лента), `src/routes/tasks.tsx`, общий layout с навигацией в `__root.tsx`.
- Загрузка файлов: через Supabase Storage, путь файла кладётся в `photos.file_path`, публичный URL рендерится в карточке.
- Серверные валидации — `createServerFn` с zod, чтобы при переезде на Amvera эту же схему можно было переиспользовать на Express.
- В шапке — индикатор «бэкенд: Cloud / Amvera» (для отладки в dev-режиме).
