# Amvera Proxy для сайта на Lovable

Прокси на nginx, который позволяет открывать сайт из РФ без VPN.
Проксирует фронт (Lovable) и Supabase под одним российским доменом.

## Что внутри

- `Dockerfile` — образ на базе `nginx:alpine`
- `nginx.conf` — основной конфиг с правилами проксирования
- `amvera.yml` — манифест для Amvera

## Как развернуть

### 1. Опубликовать сайт в Lovable
Получишь адрес вида `my-app.lovable.app`. Сообщи его мне (или замени сам в `nginx.conf` все `REPLACE_ME.lovable.app` на свой).

### 2. Создать репозиторий на GitHub
- Новый пустой репозиторий, например `mchs-proxy`
- Загрузить туда эти 3 файла (Dockerfile, nginx.conf, amvera.yml)

### 3. Создать приложение на Amvera
- Тип: **Docker**
- Подключить созданный GitHub-репозиторий
- Тариф: минимальный достаточно (это просто прокси)

### 4. Привязать домен
- В настройках приложения Amvera → Доменные имена
- Добавить свой `.ru` домен
- Прописать у регистратора домена A-запись на IP, который выдаст Amvera
- Дождаться выпуска SSL (обычно 5–30 минут)

### 5. Настроить Supabase Auth
В Lovable Cloud → Auth → URL Configuration добавить:
- `https://ваш-домен.ru` в Site URL и Redirect URLs

Иначе Google-логин и сброс пароля не будут работать с нового домена.

## Проверка

После деплоя:
- `https://ваш-домен.ru/healthz` → должно отдать `ok`
- `https://ваш-домен.ru/` → должен открыться сайт
- В DevTools → Network: запросы к Supabase должны идти на `/supabase/...`, а не на `supabase.co`

## Если что-то не так

- **«502 Bad Gateway»** — проверь, что заменены все `REPLACE_ME.lovable.app` и сайт опубликован
- **Запросы идут на supabase.co напрямую** — `sub_filter` не сработал; убедись, что в `proxy_set_header Accept-Encoding ""` пустая строка (браузер не должен получать gzip от апстрима до подмены)
- **Realtime/WebSocket не работают** — проверь, что Amvera пропускает WS на 80 порт (по умолчанию пропускает)
